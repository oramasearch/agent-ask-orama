# agent-ask-orama v0.1.1

**Released 2026-10-19. A patch release.** One change since [v0.1.0](v0.1.0.md): prompt **v14**, which
answers questions about using Lake from Lake's own Docs. Private repository and image,
`docker.io/oramasearch/agent-ask-orama:v0.1.1`.

This release is the tree of `dev` at `4058229` (v0.1.0, the v0.1.0 image digest in its notes
([#32](https://github.com/oramasearch/agent-ask-orama/pull/32)), and
[#33](https://github.com/oramasearch/agent-ask-orama/pull/33)) with these notes and the version.

## What changed

### How-to questions are answered from the Docs (prompt `v14`) — #33

"How do I load my first dataset?", the first suggestion on Lake's home, was answered with a "Lake
Console → datasets" page, an "Upload dataset" button and Parquet, none of which Lake has
([lake#817](https://github.com/oramasearch/lake/issues/817)). Prompt v14 adds *Questions about using
Lake: answer from the Docs*:

- read `list_docs` with the subject's words, then `get_doc`, and answer from that guide; say so when
  no guide covers the question;
- name pages, tabs and buttons exactly as the guide and the navigation show them, as an arrow path
  (**Data → Datasets → Load data → Upload**), and never invent or rename one;
- link each page and the guide;
- name only the formats and limits the guide states.

v14 also says "in Lake" where v13 said "in Lake Console". v13 is kept in `prompts/`. Both Docs
capabilities are public reads, so the turn can call them with the person's key; nothing new is
written.

It pairs with [lake#830](https://github.com/oramasearch/lake/pull/830), in lake
[v0.3.0](https://github.com/oramasearch/lake/releases/tag/v0.3.0), which makes the Datasets guide
carry the exact answer. Against an older Lake the agent still reads that Lake's guide.

### A `how_to` eval case

`evals.py` grades the home's question by rules: the answer must read the Docs, name and link
**Data → Datasets → Load data** (`/train/data`), and name no refused format and no "Lake Console"
page. A sentence that turns a person away from a refused format ("Parquet is not accepted: save it as
CSV first") does not count as offering it. See [`docs/how-to/README.md`](../how-to/README.md).

## Not included

Unchanged from [v0.1.0](v0.1.0.md#what-it-does-not-include): no conversation memory across restarts,
no explicit workspace ids, no idle backoff on the bus, no live `methodology_draft` eval, and no
live eval results for prompts v12, v13 or v14.

## Known issues

Security-relevant first. All open at this tag; none is new.

1. [#12](https://github.com/oramasearch/agent-ask-orama/issues/12): no explicit `workspace_id` on
   data-plane calls and delegations, and no idle backoff on the bus.
2. [#27](https://github.com/oramasearch/agent-ask-orama/issues/27): the draft's lock hashes are read
   from `pypi.org`, not confirmed reachable from the pod, and no live `methodology_draft` eval.
3. [#25](https://github.com/oramasearch/agent-ask-orama/issues/25),
   [#23](https://github.com/oramasearch/agent-ask-orama/issues/23): the live evals have not run on
   v12, v13 or v14, nor the count evals.
4. [#3](https://github.com/oramasearch/agent-ask-orama/issues/3): models are listed by project id
   instead of project name.
5. The `how_to` eval's refusal check is a word list: "Parquet is unsupported" still counts as
   offering Parquet. It errs strict.

## Where it runs

Nowhere yet. The operator's default Agent Library (orama-operator `internal/controller/lake_defaults.go`
on `dev`) names `oramasearch/agent-ask-orama:v0.1.0`, which every LakeSet member takes. Moving it to
`:v0.1.1` is a separate operator change, rolled through dev → testing → staging → prod.

## The image

Built from the tag `v0.1.1` on the cluster BuildKit with `build-agent.sh`, the same Dockerfile as
v0.1.0, then tagged `:v0.1.1` on that digest without rebuilding. The digest is recorded here once it
is built.
