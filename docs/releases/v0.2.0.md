# agent-ask-orama v0.2.0

**Released 2026-10-25. A minor release.** Seven pull requests since [v0.1.1](v0.1.1.md): the
2026-10-21 security-review fixes (five findings), prompt **v15** (propose only what can work) and
prompt **v16** (Lake's Quickstart model step). Private repository and image,
`docker.io/oramasearch/agent-ask-orama:v0.2.0`. Tracking issue:
[#51](https://github.com/oramasearch/agent-ask-orama/issues/51).

It is a minor release, not a patch, because three behaviours change for a caller: a turn is refused
when `AGENT_SERVICE_TOKEN` or `LAKE_URL` is missing, a turn's own `lake_url` is ignored, and a
conversation continues only through Lake's `prior_turn` on the bus (a direct `/v1/turn` call keeps
no conversation).

This release is the tree of `dev` at `7a044af` (everything in the table below) with these notes, the
version and the README's release line.

### Security-review fixes

These come from the [Lake pre-launch security review](https://github.com/oramasearch/orama-bridge/blob/main/docs/projects/lake-security-review/report.md)
(epic [orama-bridge#223](https://github.com/oramasearch/orama-bridge/issues/223), this repo's
findings in [#41](https://github.com/oramasearch/agent-ask-orama/issues/41)).

- **Service token (#38).** `POST /v1/turn` checks the bearer with `hmac.compare_digest`. A wrong or
  missing bearer is `401`; with no token configured every turn is `503`.
- **Credential destination (#40).** Every Lake read and the model gateway use `LAKE_URL` with the
  turn's bearer. A turn that names another host, scheme or port is served from `LAKE_URL` anyway.
- **Conversation ownership (#46).** `lake_bus.turn_body` passes the claim reply's `task_id`,
  `customer_id` and `workspace_id` to the turn as `claim`. Another account, a member using another
  `kind`, an invalid claim and every direct `/v1/turn` call start a new, empty conversation. The
  body's `conversation_id` is still echoed, never used as a memory key.
- **Bus backpressure (#47).** A slot is taken before `claim_agent_task`; while every worker is busy
  nothing more is received. One customer holds at most `workers - 1` workers. At most 256 dispatch
  rows (no body, no credential) wait in the process.
- **Bounded memory, no trace on disk (#48).** Least recently used conversations and the oldest whole
  turns are dropped past the limits below. A turn logs one line (`trace_id`, kind, prompt version,
  conversation id, rounds, outcome), never the message, the answer or the key. `TRACE_DIR` is
  ignored and the `Dockerfile` no longer sets it.

### Prompt v15: propose only what can work (#49)

On lake-dev Ask Orama proposed `compile_intent` on a project that did not exist, then pointed the
person back at the failed proposal. v15:

- reads the project a proposal names before recording it (`get_project` as the person) and refuses
  a missing one in the turn, with how to go on; a `compile_pipeline` with `create_project` for a
  taken name is refused as `conflict`;
- proposes a new project's pipeline as one `compile_pipeline` with `create_project: true`;
- reads Lake's record of the conversation's proposals (`context.proposals`: pending, confirmed,
  failed with its error, withheld) as the truth, so after a failure "create it then" gets a new,
  corrected proposal; a reply that points at a failed proposal is corrected once.

See [`docs/proposals/`](../proposals/README.md).

### Prompt v16: the Quickstart's model step (#50)

v16 is v15 plus the Quickstart (lake#1182). A turn whose `page` has `quickstart_id` carries the
dataset, its columns and the index, and:

- the dataset is known, so it never asks which one;
- it leads with ideas tied to the columns: a yes-or-no model, a derived target, M-3 clustering,
  Auto-Suggest opportunities, an analysis, an Application Agent app such as a dashboard;
- it proposes the strongest model at once as `train_quickstart`, so one Confirm starts it; a bundle
  is separate proposals; a generated corpus only when nothing else fits or the person asks.

Outside the Quickstart too, "what could I build?" is answered with ideas, never routed to a corpus
agent. See [`docs/quickstart/`](../quickstart/README.md). v14 and v15 stay in `prompts/`.

## Before it rolls: settings

| Setting | Needed | Who sets it |
|---|---|---|
| `AGENT_SERVICE_TOKEN` | **Required** now: unset or empty refuses every turn (`503`) | The operator, already (a generated random token) |
| `LAKE_URL` | **Required** now: unset or not an absolute http(s) URL refuses every turn | The operator, already |
| `AGENT_MODEL` | Unchanged | The operator, already |
| `ASK_ORAMA_CONVERSATIONS` (256), `ASK_ORAMA_CONVERSATION_TURNS` (20), `ASK_ORAMA_CONVERSATION_BYTES` (1 MiB), `ASK_ORAMA_CONVERSATIONS_BYTES` (64 MiB), `ASK_ORAMA_CONVERSATION_IDLE_SECONDS` (3600) | Optional; defaults apply | Nobody today |
| `AGENT_BUS_WORKERS` (4), `AGENT_BUS_TENANT_WORKERS` (workers - 1) | Optional; defaults apply | Nobody today |
| `TRACE_DIR` | No longer read | The operator still sets it and a `/tmp` volume; both are unused |

Nothing new is needed from the operator. v15 and v16 work best with the Lake that carries
[lake#1198](https://github.com/oramasearch/lake/pull/1198) (`compile_pipeline`'s `create_project`,
`context.proposals` on each turn) and [lake#1199](https://github.com/oramasearch/lake/pull/1199) (the
Quickstart conversation, `derived_target` and M-3 on `train_quickstart`). Both are merged into lake's
`dev` and are not in a lake release yet (lake v0.7.0 has neither). Against an older Lake: a new
project's proposal is withheld by Lake's schema, the turn has no proposal record to read, and a
Quickstart proposal with `derived_target` or M-3 is withheld with the reason. The agent's own
project check works with any Lake.

## Not included

- No conversation memory across restarts: conversations are in memory, now bounded.
- No explicit workspace ids on data-plane calls, and no idle backoff on the bus
  ([#12](https://github.com/oramasearch/agent-ask-orama/issues/12)).
- No startup failure when `AGENT_SERVICE_TOKEN` is missing (turns are refused instead), and no
  per-service or per-launch authentication ([#45](https://github.com/oramasearch/agent-ask-orama/issues/45)).
- No live eval results for prompts v12 to v16, and no live `methodology_draft` eval.

## Where it has run

**The v0.2.0 tree has not run on the dev environment.** On the dev member of `lake-nonprod` only
agent-autosuggest had a `dev-<sha>` pin; every other library agent, Ask Orama included, runs the
operator's default `oramasearch/agent-ask-orama:v0.1.0`. The browser check of the Quickstart on
lake-dev (lake#1182) was the coordinator's and is not part of this release's proof.

The image is built from the tag `v0.2.0` on the cluster BuildKit after the release, and its digest
is recorded here in a follow-up. Rolling it is a separate change through the operator's set files,
dev → testing → staging → prod.
